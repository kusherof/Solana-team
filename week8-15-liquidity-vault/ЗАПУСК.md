# Как запустить Liquidity Vault: пошагово, с нуля (Windows)

Инструкция для Windows 10/11. Anchor и локальный блокчейн нормально работают только в Linux, поэтому всё запускаем внутри **WSL** (Ubuntu внутри Windows).

Общий порядок:
1. Установить WSL и инструменты (один раз, примерно 30–40 минут).
2. Проверить проект локально: тесты (примерно 10 минут).
3. Задеплоить в devnet и пройти сценарий.
4. Запустить сайт и проверить в Phantom.

---

## Шаг 1. Установить WSL (Ubuntu)

1. Нажмите «Пуск», введите **PowerShell**, кликните правой кнопкой → **Запуск от имени администратора**.
2. Введите:
   ```powershell
   wsl --install -d Ubuntu
   ```
3. **Перезагрузите компьютер.**
4. После перезагрузки откроется окно Ubuntu (если не открылось, найдите «Ubuntu» в «Пуск»). Придумайте имя пользователя и пароль.
   Пароль при вводе не отображается, это нормально.

Дальше **все команды вводятся в окне Ubuntu**, не в PowerShell.

> Работайте в домашней папке Linux (`~`), а не в `/mnt/c/...`: на диске Windows сборка идёт в разы медленнее.

## Шаг 2. Установить инструменты (один раз)

Копируйте блоки по одному и ждите окончания каждого.

**2.1. Системные пакеты**
```bash
sudo apt update && sudo apt install -y build-essential pkg-config libssl-dev libudev-dev git curl
```

**2.2. Rust**
```bash
curl --proto '=https' --tlsv1.2 -sSf https://sh.rustup.rs | sh -s -- -y
source ~/.cargo/env
rustc --version
```
Ожидаем: `rustc 1.8x...` или новее.

**2.3. Solana CLI 2.1**
```bash
sh -c "$(curl -sSfL https://release.anza.xyz/v2.1.21/install)"
echo 'export PATH="$HOME/.local/share/solana/install/active_release/bin:$PATH"' >> ~/.bashrc
source ~/.bashrc
solana --version
```
Ожидаем: `solana-cli 2.1.21`.

**2.4. Anchor 0.31.1** (первая команда компилируется 5–15 минут)
```bash
cargo install --git https://github.com/coral-xyz/anchor avm --force
avm install 0.31.1
avm use 0.31.1
anchor --version
```
Ожидаем: `anchor-cli 0.31.1`.

**2.5. Node.js 20**
```bash
curl -o- https://raw.githubusercontent.com/nvm-sh/nvm/v0.40.1/install.sh | bash
source ~/.bashrc
nvm install 20
node --version
```
Ожидаем: `v20...`.

**2.6. Кошелёк для разработки**
```bash
solana-keygen new
```
Нажмите Enter (без пароля). Команда покажет **seed-фразу**: сохраните её у себя и никуда не выкладывайте.
Ключ ляжет в `~/.config/solana/id.json`. Этот файл **никогда не коммитим** (он уже в `.gitignore`).

## Шаг 4. Проверить всё локально (без devnet и без SOL)

**4.1. Собрать Raydium CLMM для локального блокчейна** (один раз, примерно 3–5 минут)
```bash
npm run build:raydium-local
```
В конце: `OK: .../tests/fixtures/raydium_clmm.so, admin = ...`

**4.2. Unit-тесты формул долей**
```bash
npm run test:unit
```
Ожидаем: `test result: ok. 8 passed`.

**4.3. Все интеграционные тесты** (первая сборка программы займёт 3–5 минут)
```bash
npm test
```
Скрипт сам запустит локальный блокчейн с нашей программой и Raydium. Ожидаем в конце:
```
  Неделя 8: каркас
    ✔ создаёт vault, share-токен и хранилище
    ...
  Неделя 13: позиция в CLMM-пуле
    ✔ все выводят свои доли; vault пуст

  20 passing
```
Если видите **20 passing**, программа работает.

## Шаг 5. Деплой в devnet

**5.1. Переключиться на devnet и получить SOL**
```bash
solana config set --url devnet
solana address
solana airdrop 2
solana balance
```
На деплой нужно **примерно 5 SOL**. `solana airdrop` даёт по 1–2 SOL и часто упирается в лимит.
Надёжнее: https://faucet.solana.com → вставить адрес из `solana address` → Devnet → получить SOL (можно несколько раз, войдя через GitHub).

**5.2. Свой адрес программы** (обязательно, иначе деплой упадёт)
```bash
anchor keys sync
```
Команда запишет адрес вашей программы в `lib.rs` и `Anchor.toml`.

**5.3. Сборка для devnet и деплой**
```bash
npm run build:devnet
anchor deploy --provider.cluster devnet
```
Ожидаем в конце: `Program Id: <АДРЕС>` и `Deploy success`. Этот адрес — **ваша программа в devnet**, запишите его в таблицу в README.

## Шаг 6. Сценарий в devnet (недели 8–13)

Каждая команда печатает ссылку на транзакцию в Explorer и сохраняет её в `deployments/devnet.json`.

```bash
npm run devnet:pool                  # неделя 11: токены A и B, пул Raydium, своя позиция
npm run vault -- init                # неделя 8: создать vault и свою карточку
npm run vault -- deposit 1000        # неделя 9: внести 1000 токенов A
npm run vault -- withdraw 100        # неделя 10: вывести 100 share
npm run vault -- configure           # неделя 12: привязать пул, создать хранилище B
npm run vault -- swap a2b 450        # неделя 12: обмен
npm run vault -- swap-fail a2b 100   # неделя 12: обмен, отклонённый из-за slippage (так и должно быть)
npm run vault -- open 10             # неделя 13: позиция ±10%
npm run vault -- trade 4 200         # обмены «другого трейдера», чтобы появились комиссии
npm run vault -- collect             # неделя 13: собрать комиссии
npm run vault -- close               # неделя 13: закрыть позицию
npm run vault -- swap b2a all        # вернуть весь B в A
npm run vault -- status              # посмотреть состояние vault
npm run vault -- withdraw 900        # вывести остаток
```

После этого откройте `deployments/devnet.json`: там все адреса (`mintA`, `pool`, `vault`…) и подписи транзакций (`txs`).
Перенесите их в таблицу «Devnet: адреса и транзакции» в README.

## Шаг 7. Сайт (веб-интерфейс)

**7.1. Запуск**
```bash
cd app
npm install
npm run dev
```
Ожидаем: `Local: http://localhost:5173/`. Откройте этот адрес в обычном браузере Windows (Chrome/Edge), WSL пробрасывает его сам.

**7.2. Phantom в режиме devnet**
1. Установите расширение Phantom.
2. Phantom → Настройки → **Developer Settings** → включить **Testnet Mode** → выбрать **Solana Devnet**.

**7.3. Импортировать в Phantom тот же кошелёк** (он админ vault и у него есть токены A). Выведите ключ:
```bash
cd ~/Solana-team/week8-15-liquidity-vault
node -e "const {utils}=require('@coral-xyz/anchor');console.log(utils.bytes.bs58.encode(Buffer.from(require(process.env.HOME+'/.config/solana/id.json'))))"
```
Phantom → «Добавить кошелёк» → **Импортировать приватный ключ** → вставить строку.
Это учебный devnet-ключ, никогда не используйте его для настоящих денег.

**7.4. Проверка на сайте**
- Нажать **Select Wallet** → Phantom → подключить.
- Вкладка **Пользователь**: видны баланс токена A, share-токены, доля. «Внести» 100 → в блоке «Транзакции» зелёная точка и ссылка на Explorer.
- Вкладка **Администратор**: «Узнать курс» → «Обменять» (~половину) → «Открыть позицию» → «Собрать комиссии» → «Закрыть позицию» → обменять B → A («Всё») → вернуться во вкладку Пользователь → «Вывести».

## Частые ошибки

| Ошибка | Что делать |
|---|---|
| `command not found: anchor / solana` | Выполните `source ~/.bashrc` или откройте новое окно Ubuntu |
| `feature edition2024 is required` | Не удаляйте `Cargo.lock` из репозитория: в нём зафиксированы совместимые версии. Верните его: `git checkout Cargo.lock` |
| `Your configured rpc port: 8899 is already in use` | Остался старый локальный блокчейн: `pkill -f solana-test-validator` и запустите снова |
| `DeclaredProgramIdMismatch` | Не выполнен `anchor keys sync`. Выполните его, затем `npm run build` (или `npm run build:devnet`) |
| `airdrop request failed` / `rate limit` | Используйте https://faucet.solana.com |
| `insufficient funds` при `anchor deploy` | Не хватает SOL, нужно около 5 |
| `Error: Account does not exist` в скриптах vault | Не выполнен предыдущий шаг (сначала `devnet:pool`, потом `init`, потом `configure`…) |
| `VaultNotIdle` при депозите/выводе | Это защита: средства в позиции или в токене B. Закройте позицию (`close`) и обменяйте B обратно (`swap b2a all`) |
| На сайте «Адрес vault не настроен» | Сначала пройдите шаг 6 (`devnet:pool` и `vault -- init`), они заполнят `deployments/devnet.json` |
| Сайт не видит кошелёк | В Phantom должен быть включён Testnet Mode → Solana Devnet |
